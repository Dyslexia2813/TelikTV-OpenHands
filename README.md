# TelikTV — плеер «Живая природа» для Android TV

Максимально лёгкое приложение для ТВ-приставок (проверялось под MXQ Pro 4K).
При запуске сразу открывает и воспроизводит прямой эфир канала
«Живая природа» с https://telik.live/zhivaya-priroda.html — без меню,
кнопок, настроек и splash-экрана.

## Что делает приложение

1. Достаёт подписанную ссылку на HLS-поток (см. `AGENTS.md` про цепочку).
2. Играет её через ExoPlayer (`media3`) с аппаратным декодированием.
3. При ошибке, зависании или потере сети — сам перезапускает поток.

Ничего лишнего: одна Activity, чёрный фон, один `SurfaceView`.

Если что-то не запускается, приложение показывает причину текстом по центру
экрана и пишет подробности в logcat под тегом `TelikTV`:

```bash
adb logcat -s TelikTV
```

## Требования

- Android 7.0+ (API 24), landscape, управление с пульта.
- Интернет.

## TLS на Android 7.0

Поток отдаётся по HTTPS с сертификатом Let's Encrypt, цепочка которого
завершается корнем `ISRG Root X1`. Android 7.0 этот корень ещё не содержит
(он появился только в 7.1.1), поэтому на части приставок все HTTPS-запросы
падают на этапе рукопожатия — визуально это выглядит как чёрный экран.

Чтобы это не зависело от версии прошивки, корни `ISRG Root X1` и `ISRG Root X2`
лежат в `app/src/main/res/raw/` и добавляются к системным через
`res/xml/network_security_config.xml`. Дополнительно `TlsTrust` собирает
объединённое хранилище для собственных сокетов резолвера.

## Переключение потока (зеркал)

Плеер отдаёт один и тот же канал под двумя адресами:

```
tvcdnpotok.com/2025/index.m3u8?wmsAuthSign=…  или  tvlife.live/2025/index.m3u8?wmsAuthSign=…
```

Это **не разные качества** — сегменты с обоих адресов побайтово идентичны
(совпадает md5). Это две точки входа на один CDN, поэтому переключение между
ними влияет на устойчивость, а не на картинку.

- **Автоматически:** если первый адрес не отвечает, приложение само берёт второй.
- **Вручную:** кнопки **влево / вправо** на пульте переключают адрес; выбранный
  номер показывается в центре экрана и гаснет через 3 секунды.

Сам поток — уже 1080p (H.264 Main@4.0, прогрессивный, 4:2:0) при битрейте
≈3–5 Мбит/с. Вариантов качества у источника нет: плейлист не содержит
`EXT-X-STREAM-INF`, а `master.m3u8` и подобные пути отдают 404.

## Сборка

```bash
export ANDROID_HOME=/path/to/android-sdk
export JAVA_HOME=/path/to/jdk17+
./gradlew :app:assembleRelease
```

Готовый APK: `app/build/outputs/apk/release/app-release.apk`.

`local.properties` (путь к SDK) в репозиторий не коммитится — создайте его
локально:

```properties
sdk.dir=/path/to/android-sdk
```

## Установка на приставку

```bash
adb connect <IP-приставки>:5555
adb install -r app/build/outputs/apk/release/app-release.apk
```

Или скопируйте APK на флешку и установите любым файловым менеджером
(разрешите установку из неизвестных источников).

Release-APK подписан debug-ключом, чтобы его можно было поставить без
отдельной настройки подписи. Для публикации замените `signingConfig` в
`app/build.gradle.kts` на свой keystore.

## Размер и потребление

- Release APK ~1.1 МБ (R8 + shrinkResources).
- Один `classes.dex`, без нативных `.so` и тяжёлых библиотек.
- Никаких анимаций и лишних экранов — минимум RAM/CPU.

## Поведение

| Событие | Реакция |
| --- | --- |
| Ошибка плеера | Перезапуск через 2 с (задержка растёт до 30 с) |
| Зависание потока | Watchdog по позиции воспроизведения, перезапуск |
| Потеря сети | Ждём появления сети и запускаем заново |
| Истечение токена | Ссылка перезапрашивается при каждом перезапуске |
| Экран | Не гаснет (wake lock + FLAG_KEEP_SCREEN_ON) |
| Влево / вправо | Ручное переключение адреса потока |
| OK / Menu / Info | Панель диагностики на экране (гаснет через 60 с) |

## Диагностика на экране

Компьютер для диагностики не нужен: нажмите **OK** (или **Menu**, **Info**) на
пульте — появится панель прямо поверх видео. Она обновляется раз в секунду и
сама гаснет через минуту. Повторное нажатие скрывает её сразу.

Панель показывает:

| Строка | Что означает |
| --- | --- |
| `Поток` | Номер зеркала и его хост (меняется при переключении влево/вправо) |
| `Видео` | Разрешение и частота кадров |
| `Кодек` | Профиль кодека, например `avc1.4D402A` |
| `Битрейт` | Битрейт потока и текущего сегмента |
| `Декодер` | Имя декодера, выбранного системой |
| `Тип` | `аппаратный` или `программный` — **главный показатель** |
| `Пропуск` | Сколько кадров пропущено и суммарное время пропуска |
| `Сеть` | Оценка пропускной способности канала |
| `Загрузка` | Реальная скорость загрузки сегментов |
| `Буфер` | Сколько секунд видео в запасе |
| `Позиция` | Позиция воспроизведения |
| `Состояние` | Состояние плеера и факт воспроизведения |
| `Дорожки` | Видео/аудио дорожки, `+` — выбранная |

Если в строке `Тип` написано `программный`, значит слабый процессор декодирует
видео сам, без аппаратного ускорения — это и есть причина пропуска кадров.
`Пропуск` при этом будет расти.

## Диагностика через adb (если есть компьютер)

Этот способ не обязателен — всё то же самое показывает панель выше. Логи идут
под тегом `TelikTV`:

```bash
adb connect <IP-приставки>:5555

# живой лог только по приложению
adb logcat -s TelikTV

# очистить буфер и запустить приложение заново
adb logcat -c
adb shell am force-stop live.telik.tv
adb shell monkey -p live.telik.tv -c android.intent.category.LAUNCHER 1

# ошибки медиакодека (пропуск кадров, уход в программный декодер)
adb logcat -s TelikTV MediaCodec VideoCapabilities OMXClient

# состояние сети и DNS
adb shell dumpsys connectivity | head -40
```

Что искать в выводе:

- `resolved stream 1/2: https://…` — какой адрес выбран (ручное переключение
  меняет эту цифру).
- `playback error …` — код ошибки ExoPlayer с причиной.
- `resolve failed …` — не удалось получить ссылку на поток.


## Структура

```
app/src/main/java/live/telik/tv/
├── MainActivity.java     — плеер, ретраи, immersive, wake lock, диагностика
├── StreamResolver.java   — получение ссылки на поток (raw-socket HTTP)
├── Diagnostics.java      — сбор статистики воспроизведения для панели
└── TlsTrust.java         — объединённое хранилище корней для резолвера

app/src/main/res/raw/     — корневые сертификаты ISRG (Let's Encrypt)
app/src/main/res/xml/     — network security config
```
